# AirRadar AI

Асинхронный мониторинг Telegram-каналов воздушных/военных угроз в реальном
времени с нейросетевым сжатием (локальная Ollama, модель `qwen2.5:3b`) и
пере публикацией в свой канал.

## Что делает

```
Telethon (исходные каналы)
  └─► быстрый фильтр по ключевым словам      [fast_filter.py]
        └─► дедупликация повторов (TTL ~60с) [dedup.py]
              └─► сжатие через Ollama         [ai_summarizer.py]
                    └─► эмодзи-заголовок      [sticker.py]
                          └─► публикация      [publisher.py → Bot API]
```

Если Ollama недоступна или вернула ошибку — публикуется **оригинальный** текст
с эмодзи-заголовком. Скрипт при этом не падает.

## Требования

- **Python 3.10+** (на машине должен стоять реальный интерпретатор, а не
  заглушка Windows Store — `python --version` должен показывать версию).
- **Ollama** запущенная локально (`http://localhost:11434`) с моделью
  `qwen2.5:3b`. Поставить модель: `ollama pull qwen2.5:3b`.
- Telegram-аккаунт для User API (чтение каналов) **и** бот для публикации.

## Установка

```bash
pip install -r requirements.txt
```

## Настройка

1. Скопируй `.env.example` в `.env`:
   ```bash
   cp .env.example .env
   ```
2. Заполни `.env`:
   - `TG_API_ID` / `TG_API_HASH` — с https://my.telegram.org (API development tools)
   - `BOT_TOKEN` — от @BotFather; **бот должен быть админом** в `TARGET_CHANNEL`
   - `TARGET_CHANNEL` — куда публикуем (`@username` или `-100…`)
   - `SOURCE_CHANNELS` — что слушаем (через запятую: `@a,@b,-100…`)
   - Ollama и рантайм-настройки уже выставлены по умолчанию

## Запуск

```bash
python main.py
```

При первом запуске Telethon запросит номер телефона и код подтверждения
(создаст файл сессии `airradar.session`; повторно спрашивать не будет).

## Архитектура (краткая карта файлов)

| Файл | Назначение |
|------|------------|
| `config.py` | загрузка и валидация `.env`, дата-класс `Settings` |
| `fast_filter.py` | отсев по `KEYWORDS` до тяжёлого ИИ |
| `sticker.py` | `get_sticker_header()` — эмодзи-заголовок по типу угрозы |
| `ai_summarizer.py` | Ollama + системный промпт Qwen + fallback на оригинал |
| `dedup.py` | TTL-кеш повторов (sha256 от нормализованного текста) |
| `publisher.py` | отправка в канал через Bot API (aiohttp, Markdown, plain-retry) |
| `main.py` | оркестрация: Telethon, конвейер, healthcheck, shutdown |

## Поведение при сбоях

- **Ollama недоступна / таймаут / ошибка** → публикуется оригинал + эмодзи.
- **Telegram отверг Markdown** → автоматический повтор plain-текстом.
- **Бот без прав / неверный канал** → лог ошибки, скрипт продолжает работу.
- **Повтор сообщения в окне `DEDUP_TTL`** → игнорируется.
- **Потеря соединения Telethon** → авто-реконнект (встроен в Telethon).

## Логирование

Уровень задаётся в `LOG_LEVEL` (`DEBUG`/`INFO`/`WARNING`/`ERROR`). На `DEBUG`
видны хеши дедупликации и ответы Ollama; Telethon приглушен до `WARNING`,
кроме режима `DEBUG`.
