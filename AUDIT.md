## 1. Что это

Telegram-бот мониторинга воздушных угроз Украины: читает мониторинговые
каналы (Telethon, User API), фильтрует мусор, сжимает посты локальной/облачной
LLM, агрегирует подтверждения инцидентов и публикует:
- в целевой Telegram-канал (Bot API, publisher.py),
- в ЛС подписчикам по регионам (Telethon-бот, персональные фильтры/ночной режим),
- на автономную карту угроз (map_live.html + /api/threats, GitHub Pages),
- проактивные прогнозы «когда відбій» и «можлива нова тривога» (статистика волн).

Стек: Python 3.10+, Telethon, aiohttp, SQLite, Ollama (qwen2.5:3b) или Groq
(llama-3.1-8b), Leaflet (карта), systemd (VPS-деплой, unit-файлы *.service).

## 2. Поток данных (конвейер одного сообщения)

```
Telethon NewMessage (SOURCE_CHANNELS)
→ media_ocr (если фото: Groq vision OCR)
→ fast_filter.clean_signature (срез подписей каналов: «✙ Розвідка неба ✙»,
  t.me-ссылки, «Підписатись», хвосты-обрывки «✙[»)
→ fast_filter.matches_keywords (ключевые слова угроз; анти-маркеры
  ретроспективы «загинув/вчора»; джанк-фильтр «донат/доброго вечора»)
→ dedup (TTL-окно, гибрид память+SQLite)
→ weapon_classes.classify_weapon (canonical класс: uav/shahed/ballistic/...)
→ analytics._detect_stage (past / imminent / potential / unknown;
  формулы «загроза застосуван...» = imminent)
→ ai_summarizer.summarize (LLM-сжатие до 1 фразы ≤25 слов; «IGNORE», если
  пост не про оперативную угрозу; safe_summary режет выдумки: числа и типы
  оружия обязаны быть в исходнике, иначе fallback на исходник)
→ incident_fusion.extract_incident_fact (цель/происхождение/количество;
  сборные сводки → destination='multi')
→ database.merge_incident_fact (окно 20 мин; статус: reported →
  corroborated (2+ независимых группы) → officially_confirmed)
→ ГАРД: CRITICAL (балістика/крилаті/КАБ…) от ОДНОГО источника в канал
  НЕ публикуется до подтверждения (CRITICAL_NEEDS_CONFIRMATION=1);
  в БД/карту пишется сразу
→ aggregator (окно 35 сек: один инцидент = один пост; байпас: отбой,
  подтверждённое, материальное обновление)
→ alert_renderer.render_evidence_alert (evidence-first формат, см. §5)
→ publisher.send (канал, HTML, бренд-строка-ссылка)
→ _notify_subscribers (ЛС по регионам: ночной режим, фильтры типов,
  київські берега, кнопки «✅ Корисно / ➖ Шум»)
→ БД: threat_events (стадии), threats (карта), incidents, alerts (волны)
→ health_server /api/threats + generate_map.py (авто-снапшот карты)
```

Фоновые циклы (main.run): healthcheck LLM, дайджесты (утро/вечер),
_pre_wave_loop каждые 60 сек:
- standdown_notice: во время тревоги «⏳ відбій орієнтовно за ~N хв»
  (медиана «останній політ → відбій» по региону, 3+ эпизода, одно сообщение
  на эпизод; идёт в ЛС И в канал);
- pre_wave_notice: после отбоя «⚠️ можлива нова тривога» в окне
  [медиана−10 мин, медиана+15 мин] паузы «відбій → нова тривога»
  (одно на эпизод; идёт в ЛС И в канал).

Ещё фоновые циклы (§7в): _sirens_loop — опрос alerts.in.ua раз в 60 c
(SIRENS_POLL_INTERVAL): переходы ВКЛ/ВЫКЛ логируются и пишутся в БД,
None от ошибки сети ≠ «тревог нет»; _accuracy_post_loop — недельный
пост «🎯 Точність прогнозів» в канал (день/час по Киеву, дедуп по
киевской дате в памяти). Обе задачи регистрируются в run() с graceful
cancel в finally.

## 4. Гарды правды (анти-фейк) — что уже встроено

1. IN_FLIGHT_ONLY=1: в канал только «уже летит» (imminent) или отбой.
2. CRITICAL_NEEDS_CONFIRMATION=1: одиночная «загроза балістики» не летит в
   чат; публикуется при 2-м независимом источнике/официально. В БД/карте
   видна сразу (карта честнее чата).
3. LLM IGNORE: посты не про угрозу (реклама, аналитика, названия каналов,
   подписи) → игнор; звуки «чути мопед» ≠ БПЛА.
4. safe_summary: LLM не может добавить числа/типы оружия, которых нет в
   исходнике (иначе fallback на исходник).
5. «Статус: повідомлення одного джерела» удалён из постов (шум); статус
   показывается ТОЛЬКО при подтверждении («підтверджено N незалежними
   джерелами» / «офіційним джерелом»).
6. Имена исходных каналов и их подписи (✙/t.me/«Розвідка неба») вырезаются
   ДО анализа и НЕ попадают в посты; внизу только «📡 Джерело: AirRadar AI».
7. Дедупликация + окно инцидента: повтор одного события не спамит.
8. ETA публикуется только с пометкой «орієнтовно»; прогнозы помечены
   «Статистична оцінка, не гарантія. Сирени — головне джерело».
9. Стадия past (прилёты/последствия) пишется в БД (для ETA-статистики),
   но не публикуется («точки прилётов не постим»).

## 5. Примеры ответов бота (реальные форматы)

### 5.1 Полёт шахедов (подтверждённый инцидент, канал + ЛС)
```
🔴 КИЇВ ТА ОБЛАСТЬ | БПЛА (Shahed)

🕒 21:14
📍 Рух: цілі прямують з Сумська обл. на Київ та область
⏱ Типовий підліт: ~10–40 хв (орієнтовно)

⚠️ Статус: підтверджено 2 незалежними джерелами

Група БпЛА курсом на Київ, йдуть з півночі

📡 Джерело: AirRadar AI
```
В ЛС то же + кнопки «✅ Корисно / ➖ Шум / ↗ Поділитися». На карте: пин
в районе, красная зона, пунктирный вектор «Суми → Київ» с наконечником,
«➤ Суми → Київ · ≈38 хв (орієнтовно)», анимированная точка по курсу,
бейдж «🎯 на підході», если пост говорит про подход к цели.

### 5.2 Одиночная «загроза балістики» (гард сработал)
Вход от одного канала: «Загроза застосування балістичного озброєння»
→ в канал ТИШИНА. Лог: «CRITICAL без подтверждения не публикуется — ждём
2-й источник». Пост лежит в БД/карте. Через минуту второй канал даёт
«Балістика летить на Київ» → инцидент corroborated → мгновенный пост:
```
🔴 КИЇВ ТА ОБЛАСТЬ | Балістика

🕒 21:20
⏱ Типовий підліт: ~3–7 хв (орієнтовно)

⚠️ Статус: підтверджено 2 незалежними джерелами

Балістика летить на Київ

📡 Джерело: AirRadar AI
```

### 5.3 Countdown отбоя (во время тревоги, канал + ЛС)
```
⏳ Сумська область — відбій орієнтовно за ~15 хв

Чому: останнє повідомлення про ціль у повітрі було ~5 хв тому, а за
статистикою регіону (4 епізодів) від останнього поста про політ до
відбою проходить ~20 хв.

⚠️ Статистична оцінка, не гарантія. Сирени — головне джерело.
```
(если медиана исчерпана: «⏳ … — відбій орієнтовно будь-якої хвилини»)

### 5.4 Пре-вейв (после отбоя, канал + ЛС)
```
⚠️ Сумська область — можлива нова тривога

За статистикою регіону (3 пауз між хвилями) наступна тривога ймовірна
приблизно зараз: медіана «відбій → нова тривога» — ~50 хв.

⚠️ Статистична оцінка, не гарантія. Сирени — головне джерело.
```

### 5.5 Отбой (всегда мгновенно)
```
🟢 ВІДБІЙ — СУМСЬКА ОБЛАСТЬ — 22:41

📡 Джерело: AirRadar AI
```

### 5.6 Мусор из источника (очистка)
Вход: «Реактивний БпЛА курсом на Калинівку
✙[ Розвідка неба ](https://t.me/rozvidkaneba)✙
✙[»
→ чистка: «Реактивний БпЛА курсом на Калинівку» (✙-декор, ссылки и имена
каналов вырезаны; в посте их нет никогда).

### 5.7 Не-угроза (LLM игнор)
Вход: «У Києві чути звук, схожий на мопед» → ответ модели: `IGNORE`
→ ни поста, ни карты. Аналогично реклама/аналитика/политика.

   leave-one-out hit-rate «відбій у межах медіани» по всем регионам;

9. **Event-loop гард в bot_ui.register_handlers** (bot_ui.py, строка
   create_task): `asyncio.get_running_loop()` + fallback `task=None`
   вне loop. Раньше синхронный вызов вне loop (юнит-тесты, повторный
   импорт) падал с `RuntimeError: no running event loop` — 25 тестов
   красные. Боевой путь не изменён: в main.run() loop активен, задача
   планируется как раньше (проверено: SetBotCommandsRequest уходит).

## 7в. Роадмап-фичи 2026-09-30 (сессия «сирены + точность + зоны»,
после 8496867)

1. **Официальные сирены alerts.in.ua**: main._sirens_loop — опрос раз в
   60 c (SIRENS_POLL_INTERVAL), _sirens_fetch — чистая тестируемая
   функция; None от ошибки сети НЕ трактуется как «тревог нет»;
   переходы ВКЛ/ВЫКЛ логируются и пишутся в db.set_siren_state.
   Токен: ALERTS_IN_UA_TOKEN (без него цикл молчит).
2. **Замер latency конвейера**: main._publish_items после успешной
   публикации пишет db.record_pipeline_latency (от самого старого
   received_ts набора; legacy-алерты без received_ts пропускаются);
   PendingAlert получил received_ts: int = 0 (aggregator.py), ставится
   при отправке в агрегатор. В /status — p50/p95 за 24 ч
   (db.latency_percentiles, окно 48 ч в таблице pipeline_latency).
3. **Маркер «🎯 Торкнеться вашої зони»** в _notify_subscribers: если
   home_region подписчика входит в regions поста ИЛИ detect_city по
   тексту (city_coords.CITIES) находит его город.
4. **Режим «Укриття» (shelter_mode)**: в ЛС проходят только критичные,
   відбій и zone-hit — остальное в обычном порядке не дёргает.
5. **Недельный пост «🎯 Точність прогнозів»**: wave_forecast.
   accuracy_post_text(db) — % отбоев в пределах медианы + опережение
   сирены; честное «недостатньо даних» при мало эпизодов; main.
   _accuracy_post_loop — день/час по Киеву (ACCURACY_POST_*), дедуп
   по киевской дате в памяти.
6. **Кэш LLM-резюме**: ai_summarizer.SummaryCache (sha1+TTL+размер) +
   CachedSummarizer — кэшируются только реальные резюме, не fallback
   (SUMMARY_CACHE_TTL/SIZE; make_summarizer заворачивает при TTL>0).
7. **Эскалация Groq**: _summarize_once → (result, degraded); при
   деградации (усечение/мусор/пусто) повтор на GROQ_MODEL_STRONG.
8. **Время по Киеву**: main._kyiv_datetime/_kyiv_hour/_kyiv_date_str
   (DST вручную, UTC+2/+3) — вместо локального времени хоста.

## 8. Слабые места / идеи для улучшений (честно)

1. Словарные фильтры (KEYWORDS/маркеры) — растут вручную; нужен авто-мининг
   новых формулировок из пропущенных постов (inference_audit уже пишется).
2. merge_incident_fact матчит по (destination, stage, weapon): «на Київ» и
   «на Оболонь» могут дать разные регионы → редкие дубли инцидента.
3. ETA-статистика накапливается по классам оружия без разбивки по регионам
   (KISS), точность растёт медленно на редких классах.
4. ✅ ИСПРАВЛЕНО (см. §7б.6): merge_incident_fact(official=True) помечает
   officially_confirmed; main.py прокидывает OFFICIAL_SOURCES.
5. Прогнозы волн требуют 3+ эпизодов на регион: новые регионы молчат
   первые дни (честно, но можно seeded-медианы по соседним регионам).
6. Карта: вектор полёта строится из текста поста (маркеры «з X на Y») —
   если источник не пишет маршрут, вектора нет (только пин).
7. Нет сквозного e2e-теста «вход → пост в канале» с реальными Telegram-
   заглушками; конвейер покрыт юнит-тестами по слоям.
8. OCR/фото: groq vision распознаёт, но не верифицирует подделку скрина.
9. Night digest копит некритичное — нет приоритезации внутри дайджеста.
10. Единый стиль: часть логов RU, часть UA — унифицировать бы.
11. **Нет CI на тесты**: pytest гоняется только локально; GitHub Actions
    содержит лишь deploy-map.yml. Добавить workflow «pytest на push/PR» —
    дешёвая страховка регрессий (сейчас 261 тест, ~14 сек).
12. **requirements.txt без пинов** (`>=`): VPS-деплой может молча поднять
    мажорную версию telethon/aiohttp. Нужны пины (или lock) + smoke-тест
    импорта в CI.
13. **SQLite синхронно в async-цикле** (осознанный компромисс: WAL,
    busy_timeout 30s, threading.Lock, записи редкие — см. шапку
    database.py). При росте нагрузки/частоты записей — вынести в
    aiosqlite/executor, не переписывая API класса.
14. **Тихие except**: напр., блок публичной точности в _stats_all_text
    (bot_ui.py) глотает любые исключения без лога — при поломке метрики
    она молча исчезнет из статистики. Минимум — logger.debug с exc.
15. **Не проверено живьём**: после 8496867 — Telegram («синяя кнопка
    меню», «❌ Помилка») и GitHub Pages; после §7в — сирены/accuracy-
    пост/shelter_mode/p50-p95 на живом VPS (деплой вручную:
    sudo bash deploy.sh). Только локальные тесты.
