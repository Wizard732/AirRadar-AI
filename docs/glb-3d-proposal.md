# Предложение: объёмные GLB-модели на карте AirRadar

Статус: **предложение, ничего не скачано и не подключено.** Начинать после согласования и после того, как 2D-карта признана законченной.

## 1. Архитектура
- Остаёмся на Leaflet. 3D — отдельный необязательный слой `miniapp/map3d.js` (Three.js + `GLTFLoader`), включается кнопкой/настройкой «3D-модели», по умолчанию выключен на слабых устройствах.
- Слой — прозрачный WebGL-canvas над картой; камера синхронизируется с Leaflet по `move`/`zoom` (проекция `map.latLngToContainerPoint`, ортографическая камера, без искажений). Модели ставятся в тех же точках, что и текущие SVG-маркеры; бизнес-логики в слое нет (получает готовый список `{id, category, lat, lon, heading, count_bucket, status}`).
- Прототип сначала на одном GLB; критерий успеха — pan/zoom/resize без «отставания», ≥ 30 FPS на среднем Android, ≥ 55 FPS на ноутбуке. Если Leaflet+Three нестабилен — сравнить MapLibre GL custom layer (только по измерениям).
- Fallback: нет WebGL, потеря контекста, `prefers-reduced-motion`, батарея < 20 % или > N объектов → текущие SVG-силуэты.

## 2. Модели (набор)

| БпЛА малый / FPV | прочие БпЛА | квадрокоптер |
| Крылатая ракета | крылатые | |
| Баллистическая ракета | баллистика | |
| КАБ | авиабомбы | |
| Самолёт | авиация | |
| Неопознанный объект | неизвестно | нейтральный маркер-октаэдр |

Требования к GLB: glTF 2.0, PBR (серый металлик/матовый пластик, без цвета тревоги), ≤ 5k треугольников, ≤ 150 КБ на модель (draco/meshopt + KTX2/webp), единый масштаб (1 ед. = 1 м размаха), нос по +Z, начало координат в центре масс, без лишних узлов. Цвет угрозы несёт заливка области и бейдж UI, не материал модели.

## 3. Источники и лицензии (не скачивать до согласования)
1. **Собственные модели в Blender** (предпочтительно): силуэты по открытым фото и чертежам, без чужих ассетов — нет лицензионных рисков, полный контроль размера.
2. **Sketchfab / CGTrader / Poly Pizza** — только CC0 или CC-BY с разрешением на коммерческое/публичное использование и модификацию; для CC-BY — строка авторства в `docs/3d-assets-licenses.md` и в «Про проєкт».
3. Генерация из текста/изображений — только если лицензия сервиса разрешает коммерческое использование результата.
Для каждого файла запись: название, автор, URL, лицензия, дата, правки, локальный путь, хэш. Неизвестная лицензия = модель не используется.

## 4. Размер и производительность
- Бюджет загрузки 3D-слоя: Three.js (tree-shaken, ≈ 150 КБ gzip) + 7 моделей ≈ 0.7 МБ; грузятся лениво при включении 3D и кэшируются (Service Worker, `cache-first` для `/models/*.glb`).
- Инстансинг: одна геометрия на категорию, `InstancedMesh` до ~200 объектов; свыше порога — кластеры/SVG.
- Рендер по требованию (`renderer.setAnimationLoop` только при движении карты или анимации), пауза в скрытой вкладке, DPR ≤ 2, `powerPreference: low-power` на мобильных.
- Освобождение: `dispose()` геометрий/материалов/текстур при выключении слоя и на `webglcontextlost`.

## 5. Интеграция с публичным контрактом
Слой получает те же данные, что и SVG: категория и положение маркера (как отдаёт режим данных, выбранный владельцем). Курс модели берётся из `heading`, если поле есть, иначе модель стоит неподвижно. Слой сам ничего не запрашивает и не считает.

## 6. План работ
1. Прототип: Three.js + одна тестовая GLB (CC0) + синхронизация, замеры FPS/памяти (desktop + Android WebView).
2. Решение по Leaflet+Three против MapLibre на цифрах.
3. Модели: Blender → оптимизация (gltf-transform) → `docs/3d-assets-licenses.md`.
4. Интеграция, fallback, настройка «3D-модели», тесты (контекст потерян, нет WebGL, 500 объектов).
5. APK: размер assets, проверка на устройстве.

## 7. Риски
Размер APK/загрузки, батарея на слабых телефонах, потеря контекста WebGL, синхронизация камеры при быстром pan/zoom, лицензии внешних моделей. Каждый риск имеет fallback на SVG.
