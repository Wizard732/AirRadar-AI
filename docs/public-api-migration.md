# Миграция публичного API: матрица endpoint → поля → доступ → решение

Статус: **план, production не менялся.** Основа — `docs/public-api-contract.md` (контракт, поля, схема), уточнения архитектора учтены.

## 1. Матрица endpoint'ов
| Endpoint / файл | Текущие чувствительные поля | Доступ сейчас | Решение | Новый доступ |
|---|---|---|---|---|
| `GET /api/tracks` | `points`, `now`, `speed_kmh`, `heading`, `forecast`, `dest` | публичный | **перевести на публичный контракт** (алиас `/api/public/v1/regions`); старый ответ — только админам | публичный (урезан) |
| `GET /admin/tracks` (новый) | полный `radar_payload` | — | создать | `X-Admin-Token`, 404 при отсутствии токена в окружении |
| `tracks.json` (Pages, `radar-data`) | те же поля | публичный | заменить на `public-regions.json` + задержка; `tracks.json` с полным payload не публиковать | публичный (урезан) |
| `GET /api/threats` | `track` (курс, скорость, from/to), `origin`, `destination`, `lat/lon` пинов | публичный | убрать `track`, `origin`, `destination` из публичного ответа; точка пина → центроид региона/города из справочника | публичный (урезан) |
| `GET /api/risk?lat&lon` | `distance_km`, `bearing`, `eta_min`, `speed_kmh` | публичный | **закрыть как оракул**: серия запросов с разных точек позволяет триангулировать позицию цели. Оставить только уровень (`none/watch/imminent`) без расстояния, пеленга, ETA и скорости; лимит запросов | публичный (урезан) + rate limit |
| `GET /api/stream` (SSE) | нет данных, только `rev` | публичный | оставить; `rev` считать от публичного payload (после задержки) | публичный |
| `GET /api/stats`, `stats.json` | агрегаты | публичный | аудит полей; допустимы агрегаты без координат | публичный |
| `GET /api/alerts-history`, `alerts_hist.json` | журнал тревог по районам | публичный | оставить (официальные данные); проверить отсутствие координат | публичный |
| `impacts.json`, `impacts` в payload | координаты прилётов | публичный, задержка `IMPACT_DELAY_MIN` | **отдельный аудит**; до его итога не менять | без изменений |
| `/raions.json` | границы районов | публичный | оставить (административная география) | публичный |
| `localStorage ar_last_tracks` | полный payload в браузере | клиент | хранить только публичный контракт | клиент |
| `sw.js` | не кэширует `/api/` и `tracks.json` | клиент | добавить `public-regions.json` в исключения | клиент |

## 2. Публичный контракт (финальный) — примеры JSON
Публичный ответ (`/api/public/v1/regions`, синтетика):
```json
{
  "schema": 1, "updated_at": 1700000100, "delay_min": 10,
  "notice": "Положение показано обобщённо по району; точные координаты объектов не публикуются.",
  "regions": [
    {"region": "dnipropetrovska", "raion": "Дніпровський", "category": "drone",
     "status": "tracking", "count_bucket": "2-5", "sources_bucket": "2",
     "first_seen": 1699999200, "last_update": 1699999800, "stale": false},
    {"region": "odeska", "raion": null, "category": "missile",
     "status": "confirmed", "count_bucket": "1", "sources_bucket": "3+",
     "first_seen": 1699999500, "last_update": 1699999800, "stale": false}
  ]
}
```
Правила: время — округление до 5 минут и сдвиг на `delay_min`; `raion = null` — привязка только к области; `region` — слаг; приоритет цвета ракета > дрон > прочее; публичные статусы: `detected, confirmed, tracking, stale, lost, completed, expired` (+ `intercepted/destroyed/fell` только с подтверждением и **без привязки к точке**).

Закрытый ответ (`/admin/tracks`): текущий `radar_payload`.

## 3. Минимизация по малым выборкам
Агрегаты по району с одним событием и точным временем могут раскрывать больше. Поэтому: `count_bucket`/`sources_bucket` диапазонами, время с округлением, при `delay_min` ≥ 10; публичный ответ не содержит `id` трека (стабильный идентификатор позволил бы связывать ответы между обновлениями), вместо него — хэш `region|raion|category|bucket_time`, меняющийся каждые 5 минут.

## 4. Статусы: track_engine → lifecycle → публичный
| track_engine | lifecycle | публичный статус |
|---|---|---|
| `active`, 1 источник | `tracking` | `tracking` |
| `active`, 2+ источников | `confirmed` | `confirmed` |
| `stale` | `stale` → `lost` | `stale` → `lost` |
| `loitering` | `tracking` + признак | `tracking` |
| (нет) подтверждённый сбит/упал | `intercepted/destroyed/fell` | то же, без точки |
| (нет) отбой/завершение | `completed` → `expired` | `completed` → `expired` |

## 5. Тесты на отсутствие утечек
1. Рекурсивный обход JSON публичных ответов: запрещённые ключи `points, now, speed_kmh, speed_source, heading, heading_text, forecast, dest, track, origin, destination, lat, lon, id` (кроме разрешённых).
2. Значения: нет float с 3+ знаками после запятой в диапазоне координат Украины.
3. Те же проверки для `/api/threats`, `/api/risk`, `public-regions.json`.
4. `/api/risk`: ответ без `distance_km`, `bearing`, `eta_min`, `speed_kmh`; rate limit срабатывает.
5. SSE: только `rev`/heartbeat.
6. `/admin/tracks`: нет токена в окружении → 404; неверный → 401; верный → 200; сравнение `hmac.compare_digest` (уже в `dashboard.token_ok`, токен ≥ 16 символов).
7. Сканирование `radar.html`, `map.html`, `sw.js`, `app/www` на строки `/admin/`, `X-Admin-Token`.
8. Сравнение двух последовательных ответов: идентификаторы меняются между временными корзинами.

## 6. Админ-токен
Токен только в заголовке (не в URL), в окружении сервера; во фронтенд, APK и Pages не попадает; проверка `hmac.compare_digest`; публичный клиент закрытый endpoint не вызывает. Полный payload остаётся доступным только серверной части и админам.

## 7. План миграции клиентов
1. Серверная часть: `public_payload()` в `health_server`/новом модуле, `/api/public/v1/regions`, `/admin/tracks`, урезание `/api/threats` и `/api/risk`, `export_radar.py` пишет `public-regions.json`.
2. `radar.html`: читает `public-regions.json`/`/api/public/v1/regions`; маркер = модель в центроиде района; цвет — заливкой района (жёлтый/красный); подпись в интерфейсе «Положение показано обобщённо по району»; `localStorage` — только публичный контракт.
3. `map.html`: читает урезанный `/api/threats`; без лучей и векторов (`routeOf`, `track`).
4. APK и Pages: пересборка после выкладки сервера; проверить, что старые клиенты не ломаются (`/api/tracks` держит совместимый урезанный формат до миграции).
5. Порядок выката: серверная часть → Pages/APK → удаление совместимого формата.
6. Feature-flag `PUBLIC_MODE=region` (по умолчанию `region`); `PUBLIC_MODE=legacy` — откат одной переменной окружения.

## 8. Риски
- Клиенты на старых версиях APK ждут `points` — нужен период совместимости с урезанным `/api/tracks` (пустые `points`, `speed_kmh`=null).
- Качество «района» зависит от геокодера; для точек вне полигонов — привязка к области.
- Снижение функциональности (пропадёт прогноз «когда долетит», `risk` по адресу) — осознанное решение владельца.


## 9. Реализовано в рабочей копии (без деплоя)
- `airradar/safety/public_view.py`: `build_public`, `regions_contract`, `strip_threat`, `public_risk`, `coarsen_report`, `FORBIDDEN_KEYS`.
- `health_server.py`: `public_payload`, `/api/tracks` (публичный, совместимый формат), `/api/public/v1/regions`, `/admin/tracks` (токен), урезанные `/api/threats` и `/api/risk` (уровень, фиксированный радиус 10 км, сетка 0.1°, данные с задержкой, лимит 20 запросов/мин на IP), SSE `rev` считается от публичного payload (без `now`/`updated_at`).
- `export_radar.py`: `tracks.json` в публичном формате + `public-regions.json`; `radar_publish.sh`, `deploy-map.yml` публикуют новый файл.
- `miniapp/radar.html`: район по `raion_key`, бейдж диапазона, подпись про обобщённое положение; `miniapp/sw.js`: `public-regions.json` не кэшируется (кэш v4).
- Задержка по умолчанию 10 минут (`TRACKS_PUBLIC_DELAY_MIN`, если задана — берётся она).
- **Production-переключателя legacy нет.** Переменная `PUBLIC_MODE` игнорируется; внутренний формат доступен только в тестах (`_LEGACY_FOR_TESTS`) и через `/admin/tracks`.
- Ключ элемента (`id`) — район + категория, а не идентификатор цели.

### Тесты
`test_public_view.py` (22): запрещённые ключи, числа с 3+ знаками, фиксированные центроиды, группировка и диапазоны, округление времени, ключ по району, отсутствие побочного канала внутри 5-минутной корзины, `/api/tracks`, `/api/public/v1/regions`, `/api/risk` (только `level`/`text` + 429), `/admin/tracks` (404/401/200), env не включает legacy, SSE от публичного payload, статическое сканирование клиентов на `/admin/` и `X-Admin-Token`, совместимость старого клиента APK (`app/www/radar.html`: `positionAt`, `isNoise` на публичных треках). Весь набор: 594 passed.

### Откат
Откат версии кода (git revert коммита с публичным слоем) и перезапуск `airradar-bot`. Включения старого формата переменной окружения нет.

### Остаётся
- `map.html`: пины по городам из текста (`CITY_COORDS`) точнее района — перевести на район/центроид.
- `impacts.json` (координаты прилётов): отдельный аудит.
- APK: пересборка (в `app/www` старый клиент); старые APK работают на совместимом формате.
- Архив: `radar-data` перезаписывается одним коммитом, но кэш CDN и старые копии Pages могут жить дольше.

## 10. Решение владельца по умолчанию (2026-10-31)
Владелец принял решение: публичная карта показывает **полные данные** (позиции, курс, скорость, прогноз, ETA до пользователя), как до этой миграции; это информация для украинцев о запусках. Реализовано так:
- `PUBLIC_MODE` по умолчанию `legacy` (полные данные, задержка 0), прежнее поведение продакшена сохранено;
- режим `PUBLIC_MODE=region` включает всё, что описано выше (районы, диапазоны, задержка 10 мин, обобщённый текст, агрегированные `impacts`, урезанный `/api/risk`);
- архитектор (ChatGPT) рекомендует `region` по умолчанию; расхождение зафиксировано, решение за владельцем;
- не добавлялось: высота цели, новые вычисления скорости, публичная админ-карта; `/admin/tracks` остаётся под токеном.
Переключение — переменная окружения на сервере и перезапуск `airradar-bot`; для Pages — переменная в сервисе `airradar-radar-publish`.
