# Продуктивність

## Що виміряно
Лише логіка життєвого циклу (`evaluate_silence` + `visible`) — чистий Python, CPU, без браузера. 200 тіків на кожному розмірі, tracemalloc для пам'яті.

| Об'єктів | Час тіку | Мкс/об'єкт | Пам'ять (Python-об'єкти) |
|---|---|---|---|
| 10 | 0.008 мс | 0.79 | 15.7 KiB |
| 50 | 0.033 мс | 0.66 | 57.6 KiB |
| 100 | 0.065 мс | 0.65 | 114.2 KiB |
| 500 | 0.301 мс | 0.60 | 570.9 KiB |

Висновок: логіка стану не є вузьким місцем навіть на 500 об'єктах.

## Що НЕ виміряно (потрібна ручна перевірка)
- **FPS** карти на 10/50/100/500 маркерах у браузері — не вимірювався. Тестове середовище — `file://` без даних.
- **Пам'ять і CPU браузера** — не вимірювались.
- Навантаження Leaflet з 500 `divIcon` без кластеризації — не перевірялось; кластеризація в `radar.html` існує для >25 подій (zoom < 10), але на 500 не тестувалась.

## Вже є в коді
- Кластеризація подій у `radar.html` (клітинка 44 px, групи ≥3).
- Опитування з SSE: сервер шле лише сигнал `rev`, дані беруться з `/api/tracks`.
- Ліміт 200 SSE-клієнтів.

## Не реалізовано
spatial index, ліниве завантаження моделей, обмеження частоти анімації, вимкнення анімацій у прихованих вкладках, спрощення моделей при віддаленні. Тільки перелічено як план.
