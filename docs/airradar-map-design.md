# AirRadar: три концепции новой карты и технический план

Дата: 2026-11-03. Этап 1: концепции и план. Реализация не начата. Production, Pages, APK, коммиты, push не затрагиваются.

## 1. Три концепции

### A. «Сцена + шторка» (карта как главный экран)
- Композиция: карта на 100% экрана. Сверху тонкая строка: поиск, статус страны («3 області в тривозі»), индикатор свежести. Снизу/справа выдвижная шторка с хронологией.
- Desktop: шторка слева 360 px, сворачивается в рейл; карточка района плавает справа сверху; инструменты в одну вертикальную капсулу.
- Mobile: нижняя шторка с тремя высотами (peek 72 px / half / full), тянется жестом; карточка района заменяет содержимое шторки.
- Палитра: графит + холодный циан для официальных тревог, янтарь для неофициальных сообщений.
- Плюсы: самая читаемая карта, один паттерн на desktop и mobile, привычен. Минусы: ближе всего к референсам по ощущению, нужна выразительная типографика и иконки, чтобы не выглядеть клоном.

### B. «Табло» (статус вместо карты как главное)
- Композиция: сверху крупное табло статуса (страна → моя область → мой район) с цветом состояния, под ним карта на 60% высоты. Список областей — компактная «таблица тревог» справа.
- Desktop: двухколоночно: табло + таблица слева, карта справа. Mobile: табло-«шапка», карта, ниже лента.
- Палитра: светлая по умолчанию, плотная типографика, цвет только для состояний.
- Плюсы: быстро отвечает на вопрос «у меня тревога?», сильно отличается от референсов. Минусы: карта меньше, хуже для обзора всей страны.

### C. «Радиальный» (инструменты вокруг прицела)
- Композиция: карта на весь экран, управление через круговое меню от точки тапа (район: карточка, подписаться, поделиться, маршрут к укрытию). Постоянный UI минимален: логотип, поиск-иконка, индикатор связи.
- Mobile: естественно под большой палец. Desktop: контекстное меню по ПКМ/клику.
- Плюсы: чище всего, оригинально. Минусы: плохая обнаруживаемость функций, сложнее доступность с клавиатуры и скринридеров, тяжелее для пожилых пользователей.

### Сравнение
| Критерий | A | B | C |
|---|---|---|---|
| Читаемость карты | 5 | 3 | 5 |
| Ответ «у меня тревога?» | 3 | 5 | 3 |
| Оригинальность | 3 | 5 | 5 |
| Доступность | 4 | 5 | 2 |
| Стоимость реализации | средняя | средняя | высокая |

### Рекомендация
**A + элемент B**: сцена и шторка (A), но в верхней строке постоянный блок «Моя територія» из B с цветом статуса. Даёт читаемую карту и мгновенный ответ. От референсов отличается: светлая карточка с типографикой «табло», шторка со жестами, собственный набор линейных иконок, раздельные визуальные языки официальной тревоги (заливка + сплошная граница) и неофициального сообщения (штриховка + пунктирная граница). Решение за владельцем.

## 2. Дизайн-система (черновик, для выбранной концепции)
- Токены: фон `--bg #0f1419`, поверхность `--surface #171d24`, текст `--fg #e8edf2`, официальная тревога `--alert #ff4d4f`, неофициальное `--hint #f0b429`, отбой/спокойно `--ok #3ddc97`, нет данных `--nodata #6b7785`. Светлая тема: те же роли.
- Шрифт: Inter (системный fallback), цифры tabular.
- Иконки: единый линейный SVG-набор 24×24, линия 1.9 (уже есть в radar.html, выносим в общий спрайт).
- Состояния кнопок: default / hover / pressed / focus-visible (кольцо 2 px) / disabled; tooltip на каждой.
- Анимации: 160–220 мс, ease-out, `prefers-reduced-motion` отключает.
- Размеры: касание ≥44 px, шторка mobile ≤46% высоты в half.

## 3. Модель официальных тревог (отдельная от неофициальных)
- Источник: `sirens.py` (alerts.in.ua) через существующий payload `alerts`/`sirens`.
- Ключ события: `alert:{region_slug}:{raion_key|oblast}:{started_at}`. Стабилен, пока тревога идёт.
- Правила: новый ключ = новая тревога; пропажа из активных = отбой (`ended_at` ставится по первому снимку без неё); повторное появление в пределах 2 мин склеивается с предыдущей (антидребезг).
- Состояния: `active`, `cleared`, `no_data` (источник молчит дольше TTL), `stale` (данные старше порога).
- История: хранится `/api/alerts-history` (7 дней), клиент лишь читает.
- Неофициальное: ключ `hint:{region}:{raion}:{category}`, обновляет существующую запись вместо дубля; в UI всегда подпись «неофициально».

## 4. Архитектура
Новые компоненты (все в `miniapp/map2/`, без влияния на `radar.html` до приёмки):
| Компонент | Назначение |
|---|---|
| `data/adapter.js` | единственная точка получения данных: `public/v1/regions`, `alerts-history`, SSE; режим по настройке; кэш; опрос при ошибке SSE |
| `data/alerts-state.js` | ключи, антидубль, переходы состояний |
| `ui/sheet.js` | шторка с жестами и фокус-менеджментом |
| `ui/zone-card.js` | карточка территории |
| `ui/search.js` | поиск по `raions.json` |
| `ui/tools.js`, `icons.svg` | инструменты, спрайт |
| `map/layers.js` | заливки, границы, подложки (MapLibre GL или Leaflet; решается на этапе 2) |
| `net/status.js` | online/offline, плашки, кэш |

Переиспользуем: `raions.json`, `sw.js` (добавим новые файлы в precache), `native.js`, эндпоинты, SSE-контракт. Заново: интерфейс, слой состояний, стили.
Совместимость: Mini App открывает `app.html` → iframe; новая карта подключается теми же URL после приёмки. APK берёт файлы из `app/www` (`npm run sync`), новая папка добавляется в sync. Telegram: fullscreen API с fallback, viewport-safe-area.
