# Деплой AirRadar AI на VPS (бесплатно, 24/7)

Полный гайд: регистрация бесплатного VPS → установка → автозапуск.
Целевая платформа — **Oracle Cloud Free Tier (ARM Ampere A1)**: единственный
бесплатный сервер, на котором локальная Ollama работает комфортно (4 ядра,
24 ГБ RAM бесплатно навсегда).

> 💡 **Почему Oracle ARM?** Модель `qwen2.5:3b` требует ~4 ГБ RAM под Ollama.
> Бесплатные micro-инстансы GCP/AWS/Azure дают 1 ГБ — Ollama там не запустится.
> Oracle Ampere даёт до 24 ГБ — хватает с запасом, бот и ИИ на одной машине.

---

## Часть 1. Регистрация Oracle Cloud (один раз)

1. Перейди на https://www.oracle.com/cloud/free/ → **Start for free**.
2. Зарегистрируйся. Потребуется:
   - email, пароль;
   - **банковская карта** — для верификации (деньги **НЕ списывают**, вернётся
     авторизационный холд ~$1 и сразу спадёт);
   - выбрать **регион** (бери ближайший: Frankfurt для Европы, или где есть
     наличие Ampere — см. ниже).
3. Заверши регистрацию и зайди в https://cloud.oracle.com.

### ⚠️ Частая проблема: «бесплатный ARM недоступен»
Oracle выдаёт Ampere A1 по доступности в регионе. Если при создании инстанса
видишь *«Out of capacity»* — это лечится так:
- **Смените регион** при регистрации (Amsterdam, Frankfurt, London, Stockholm,
  Phoenix, San Jose). Где-то ёмкость свободна почти всегда.
- Либо создай инстанс через несколько часов/дней (ёмкость освобождается).
- Лимит free tier на Ampere: **всего 4 OCPU и 24 ГБ RAM** на аккаунт. Можно
  разбить на несколько маленьких инстансов, но проще — один на 4 OCPU/24 ГБ.

## Часть 2. Создание сервера (Compute Instance)

1. В консоли Oracle: **☰ Menu → Compute → Instances → Create Instance**.
2. Заполни:
   - **Name:** `airradar`
   - **Image:** Canonical Ubuntu 22.04 (или 24.04) — **по умолчанию подходит**
   - **Shape:** нажми Edit → Ampere → **VM.Standard.A1.Flex** → поставь
     **4 OCPU** и **24 GB RAM** (это максимум free tier).
   - **Networking:** оставь новую VCN по умолчанию. Обязательно должна стоять
     галочка **«Assign a public IPv4 address»**.
   - **SSH keys:** **ВАЖНО** — выбери **«Save private key pair»** и скачай
     оба файла (`*.key` и `*.key.pub`). Без приватного ключа ты не зайдёшь
     на сервер! Сохрани их в надёжное место.
3. Нажми **Create**. Через 1–2 минуты сервер поднимется. Скопируй его
   **Public IP** (виден в карточке инстанса).

### Открытие портов (опционально)
Бот и Ollama работают наружу как клиенты — **дополнительные порты открывать
не нужно**. Если захочешь стучаться к Ollama снаружи (не рекомендуется),
придётся открыть порт 11434 в двух местах: **Security List** (VCN) и
**iptables** на сервере. Для нашего случая это лишнее.

## Часть 3. Первый вход на сервер

Из терминала на своём компе (Windows — PowerShell/Git Bash):

```bash
# Приватный ключ должен быть читаем только тобой (иначе ssh ругнётся)
chmod 600 ~/Downloads/ssh-key-*.key

# Подключаемся пользователем ubuntu по IP сервера
ssh -i ~/Downloads/ssh-key-*.key ubuntu@<PUBLIC_IP>
```

При первом подключении напишут «authenticity of host can't be established» —
ответь `yes`.

> Команды ниже выполнять **на сервере** по SSH.

## Часть 4. Установка проекта (один раз)

```bash
# Обновляем систему
sudo apt update && sudo apt upgrade -y

# Клонируем твой репозиторий
git clone https://github.com/Wizard732/AirRadar-AI.git
cd AirRadar-AI

# Запускаем установщик (ставит Python, Ollama, модель, venv, systemd)
sudo bash install.sh
```

`install.sh` сделает всё за ~10 минут (больше всего времени уйдёт на скачивание
модели qwen2.5:3b ~2 ГБ). Дождись сообщения «Установка завершена».

Проверь, что Ollama и модель живы:
```bash
curl http://localhost:11434/api/tags
# Должен вернуть JSON со списком моделей, включая qwen2.5:3b
```

## Часть 5. Конфигурация (.env)

На сервере `.env` **не берётся из git** (он в `.gitignore`). Создай его вручную:

```bash
nano .env
```

Вставь свои значения (такие же, как на локалке). Можно скопировать из локального
`.env`. Минимально:
```
TG_API_ID=...
TG_API_HASH=...
BOT_TOKEN=...
TARGET_CHANNEL=@AirRadarAI
SOURCE_CHANNELS=@rozvidkaneba,...,-1003979438669
OLLAMA_URL=http://localhost:11434
OLLAMA_MODEL=qwen2.5:3b
```
Сохранить: `Ctrl+O`, Enter, `Ctrl+X`.

> 🔒 **Безопасность:** никогда не клади `.env` в git. На сервере он лежит рядом
> со скриптом и читается только им. Если хочешь — ограничь права:
> `chmod 600 .env`.

## Часть 6. Первый запуск и вход в Telegram

На сервере запускать **интерактивно** (нужно ввести телефон + код):

```bash
.venv/bin/python main.py
```

Telethon попросит:
1. **Phone:** `+380501234567` (твой номер — НЕ bot token!)
2. **Code:** код из SMS/TG
3. **Password:** твой 2FA-пароль (если включён)

После строки `Подключено как @wzrdd2... Слушаю каналы…` нажми **Ctrl+C** —
цель в том, чтобы создался файл `airradar.session`.

> ⚠️ **Важно:** Telegram-сессия привязана к номеру. Если бот уже работает на
> компе (Windows) и на сервере одновременно под одним аккаунтом — это
> подозрительная активность. **Перед деплоем на VPS останови бота на компе.**

## Часть 7. Автозапуск как сервис (24/7)

Включаем systemd-сервис, который сам стартует при загрузке сервера и
перезапускается при падении:

```bash
sudo systemctl enable --now airradar
```

Проверяем статус:
```bash
sudo systemctl status airradar
```
Должно гореть **active (running)**.

Смотрим логи в реальном времени:
```bash
sudo journalctl -u airradar -f
```
(выйти из просмотра — `Ctrl+C`)

## Часть 8. Обновление кода

Когда ты поправил код на компе и сделал `git push`, обновить сервер — одна
команда:

```bash
cd AirRadar-AI
sudo bash deploy.sh
```

`deploy.sh` сам сделает `git pull`, обновит зависимости (если надо) и
перезапустит сервис. `.env` и сессия не трогаются.

## Troubleshooting

**Бот не публикует, в логе `CHAT_WRITE_FORBIDDEN`**
Бот @AirRadar_AI_bot не админ в целевом канале. Добавь его админом с правом
публикации постов.

**Бот не ловит сообщения из приватного канала**
Убедись, что аккаунт состоит в нём подписчиком, и в логе при старте видим этот
канал в строке `Доступно каналов: N/N`.

**`Cannot find any entity` для канала**
Перезапусти сервис: `sudo systemctl restart airradar`. Скрипт при старте
обходит диалоги и резолвит каналы; после рестарта кеш обновится.

**Ollama: модель долго отвечает / timeout**
На ARM Ampere 4 OCPU модель `qwen2.5:3b` отвечает за 1–3 сек. Если медленнее —
проверь, что `HTTP_TIMEOUT=30` в `.env` и что сервер не перегружен
(`htop`).

**Telegram-сессия сломалась (частые разлогины)**
Это бывает, если сессия используется с двух IP сразу (комп + сервер).
Решение: останови бота на компе, на сервере удали `airradar.session` и
пройди вход заново (Часть 6).

## Безопасность на VPS

- **Не открывай порт Ollama (11434) наружу.** Оставь его на `localhost`.
- Поставь firewall: `sudo ufw allow OpenSSH && sudo ufw enable`.
- Не клади `.env` и `airradar.session` в git (уже в `.gitignore`).
- Периодически: `sudo apt update && sudo apt upgrade -y`.
